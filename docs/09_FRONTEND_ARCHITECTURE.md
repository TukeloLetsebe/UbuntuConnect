# FRONTEND_ARCHITECTURE.md

## Objective

Reverse engineer the frontend architecture from the existing React project.

The implementation is the source of truth.

Do not make assumptions.

---

## Inspect

- Project Structure
- Folder Structure
- Pages
- Components
- Layouts
- Routing
- Hooks
- Context Providers
- Services
- API Layer
- State Management
- Styling
- Assets
- Utilities
- Environment Configuration

---

## Analyse

Discover:

- Frontend Architecture Pattern
- Folder Organization
- Component Hierarchy
- Routing Strategy
- State Management Strategy
- API Communication Strategy
- Authentication Flow
- Authorization Strategy
- Styling Strategy
- Asset Management
- Error Handling
- Loading Strategy
- Code Organization

---

## Generate

### 1. Frontend Overview

Provide a high-level overview of the frontend architecture.

---

### 2. Project Structure

Document the project structure and explain the responsibility of each major folder.

---

### 3. Routing Architecture

Document routing, layouts, protected routes and navigation.

---

### 4. Component Architecture

Document reusable components, layouts, pages and component relationships.

---

### 5. State Management

Explain how application state is managed.

---

### 6. API Integration

Explain how the frontend communicates with the backend.

---

### 7. Authentication & Authorization

Document how authentication and authorization are implemented.

---

### 8. Styling

Document the styling approach and design system.

---

### 9. Frontend Summary

Summarize how the frontend is structured and how its major components interact.

---

## Architecture Assessment

After documenting the existing implementation, provide an assessment.

### Strengths

Identify architectural strengths.

### Weaknesses

Identify architectural weaknesses.

### Technical Debt

Identify maintainability concerns.

### Recommendations

Suggest improvements without changing the documented implementation.

---

## Rules

- The implementation is the source of truth.
- Do not invent components.
- Do not invent pages.
- Do not invent routes.
- Do not invent state management.
- Clearly separate documentation from recommendations.
- Ask for clarification if implementation is unclear.
